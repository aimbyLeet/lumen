1. What Lumen is and how it works

Lumen is open source remote access to work machines for small studios and teams. You connect to your work computer (the host) from home or another office (the client) and work as if you sat at it: steadily and comfortably, with sound, a shared clipboard, files and up to three monitors, up to 4K at 60 frames per second. The team has its own server, and the programs update themselves from it.

PartWhereWhat it does
Servera VPS (Docker) or a machine in the local network Introduces hosts and clients to each other, keeps who may connect to which machine, makes sure one client at a time is connected to a machine. Web admin panel, a download page with the installer, updates for the programs. Video never goes through the server.
Lumen Hostthe work computer with an NVIDIA card A Windows service: registers the machine on the server, shows the machine's token, sends the screen and sound, takes the mouse and keyboard. The Lumen Host window lives in the tray.
Lumen Clientthe user's computer with an NVIDIA card The organisation's server (one), the list of machines added by token, the video window.
Networkyour WireGuard or Tailscale The client connects to the host directly, by its address in this network.

Access. The host shows a token, the user enters it in the client, the server creates a request, and the administrator approves it in the admin panel; after that the client can connect. Knowing the token without the approval is not enough, and the server cannot connect without the token either: the token takes part in the encryption (Noise IKpsk2, end to end between the client and the host) and is never sent to the server. Devices talk to the server over TLS.

A session. The client asks the server to connect; the server tells the host who is coming and gives the client the host's addresses; the client tries them and talks to the host directly (UDP). The picture is HEVC Main10 compressed by NVENC on the host and decoded by NVDEC on the client.

Downloads — GitHub Releases:

  • lumen-setup-<version>.exe — the one installer for Windows; host or client is chosen while installing. The host option includes the virtual monitor driver Lumen VDD.
  • lumen-server-<version>.tar.gz — the server: its Docker image, install.sh, the download page and the installer of the same version (devices update to it).

2. Quick start: server installation

About 10 minutes. You need a server with Ubuntu 22.04 or 24.04 (x86_64) and root access over SSH; for a VPS also a domain whose DNS A record points to the server. The details are in section 5.

Step 1. Upload the archive

Download lumen-server-<version>.tar.gz from GitHub Releases and put it into /tmp on the server: with scp as below, or with any SFTP client (WinSCP, FileZilla).

scp lumen-server-0.9.0.tar.gz root@203.0.113.10:/tmp/

Step 2. Unpack and start the script

In the server's terminal:

cd /tmp
tar xzf lumen-server-0.9.0.tar.gz
sudo bash lumen-server-0.9.0/install.sh

The script speaks the system's language (usually English); --lang ru or --lang en chooses it explicitly.

Step 3. Choose a menu item

ItemWhenWhat it asks
1) Install on a clean VPS (domain, nginx, Let's Encrypt)a new VPS with nothing on it the domain (its A record already points here), an e-mail for Let's Encrypt (Enter: none), the admin's login and password
2) Install on a VPS that has nginx and other sitesnginx already serves other sites the same; other sites are not touched
3) Install in a local network (by IP, no domain)a server in the office or in a VPN the address devices use (the machine's IP is offered), the admin's login and password
4) Updatethe Lumen server is already installed here nothing: offered by default (just Enter); the database, the settings and the admin's password stay
5) Status, 6) Remove, 0) Exitsee section 14

The admin's password may be left empty (Enter): the script generates one and prints it at the end — save it. At the end the script prints the admin panel's address, the download page, the server's address for the programs and, in a local network, the certificate's fingerprint.

The provider's firewall. The script opens the ports in ufw by itself, but it does not see a firewall in the VPS provider's panel: open TCP 80, 443 and 7443 there.

Step 4. Check and clean up

sudo /opt/lumen-server/install.sh --mode status
rm -rf /tmp/lumen-server-0.9.0 /tmp/lumen-server-0.9.0.tar.gz

“Status” shows the version, whether the container runs, the addresses, the certificate's expiry (or the fingerprint) and the end of the log. The archive is not needed any more: the script copied itself to /opt/lumen-server. Next: the admin panel (section 7), the host (section 8) and the client (section 9), or straight to the first connection.

3. Requirements

  • Server: Ubuntu 22.04 or 24.04, x86_64, root over SSH. On a VPS: a public IPv4 address and a domain (for example lumen.example.com) with an A record pointing to it, for the Let's Encrypt certificate; nginx may already serve other sites. In a local network: an IP that the devices reach. Video does not go through the server: 1 vCPU and 1 GB of RAM are enough (unless the same VPS is also the WireGuard server the video goes through, see section 4). Docker is installed by the script (docker.io from Ubuntu's repository); an installed Docker is used as it is.
  • A WireGuard or Tailscale network in which the client reaches the host by IP (section 4).
  • Host and client: Windows 10 or 11 (64-bit), an NVIDIA graphics card (GTX 10xx or newer), NVIDIA driver 570 or newer (NVENC API 13.0). Administrator rights for installing the host; the client installs without them. The installer adds the WebView2 runtime if Windows lacks it (this needs the internet).
  • The client's connection: from 100 Mbit/s. The stream stays under its cap: 4K at 60 Hz takes up to about 40 Mbit/s.

4. Network: WireGuard or Tailscale

Lumen does not traverse NAT and does not relay video through its server: the client connects to the host directly, so they need a shared network in which the host is reachable by IP. WireGuard gives it (or Tailscale, which is WireGuard set up for you). Where to put the WireGuard server:

  • In the office (the office router has a public IP and forwards the WireGuard port): clients at home join the office network. Video goes directly, the latency is lowest.
  • On a VPS (the office has no public IP): hosts and clients connect to the VPS. Video goes through the VPS: its bandwidth must carry all sessions' streams in each direction, and the trip to the VPS adds to the latency.
  • Tailscale: install it on the hosts and the clients and sign in to one network; the addresses are 100.x.y.z.

The host's address is not entered anywhere: the host reports all its addresses to the server, the client tries them and connects to the one that answers. To check the network, ping the host's address in the WireGuard network from the client: ping <host address>.

The host needs inbound UDP 9000–9009: the installer opens it in Windows Firewall for every network profile (Windows often treats WireGuard and Tailscale adapters as “public”).

Other VPNs. A VPN with a TUN adapter (Happ, v2rayN, Hiddify, NekoBox and the like in TUN or “all traffic” mode) takes all routes, and Lumen's packets go into its tunnel instead of WireGuard or Tailscale. It looks like this: both programs say they are on the server, but the video window does not open. Exclusions in that VPN (excluded subnets, per-app rules) usually do not help in TUN mode: the traffic still enters its adapter, the VPN resends it itself, and that does not work for video.
  • The host gets around such a VPN by itself: it answers the client through the network adapter the client's request came in on. For that the adapter needs its own gateway (the office network or the WireGuard adapter).
  • The client reaches the host by Windows' routes. If WireGuard or Tailscale runs on the client itself, it has its own route to the host's network, and the other VPN does not interfere.
  • If it still does not work, turn that VPN off, or add a Windows route to the other side's subnet through the WireGuard network's gateway (PowerShell as administrator; a Windows route is more specific than the VPN's and wins):
route -p add 192.168.50.0 mask 255.255.255.0 10.8.0.1
Both subnets (as 192.168.50.0/24) are in Lumen Client's log: Settings → Log → “Open folder”, the latest client-…log, the session: lines. On a connection they are host_net and client_net; if the host does not answer (unreachable) — host_nets, client_nets and routes: the adapter that traffic to each of the host's addresses goes through right now.

5. Server

The server runs in Docker and is installed by install.sh from the archive lumen-server-<version>.tar.gz (section 2). The script installs, updates, shows the status and removes; the same without questions — install.sh --help.

5.1. Which option to choose

Menu itemWhenWhat it needs
1. A clean VPSa new server, nothing on it a domain (A record to the server's IP), free ports 80, 443, 7443
2. A VPS with nginxnginx already serves other sites a (sub)domain no other site uses, a free port 7443; other sites are not touched
3. A local networka server in the office or in a VPN, no domain the server's IP that devices reach; ports 443, 80, 7443 (if taken, the script offers others)

For every option: root access over SSH and an x86_64 processor. The script checks that it runs on Ubuntu 22.04 or 24.04 (anything else: it asks whether to go on) and installs curl, openssl and iproute2 if a minimal system lacks them.

5.2. A VPS with a domain (items 1 and 2)

DNS first. In the domain's panel create an A record lumen.example.com → 203.0.113.10 and wait a few minutes. To check:

getent hosts lumen.example.com

The script asks for the domain, an e-mail for Let's Encrypt (may be skipped) and the admin's login and password. Then it:

  • installs Docker, nginx (item 1) and certbot;
  • adds one site of its own to nginx for the domain: first a temporary one for Let's Encrypt's check, then the full one — HTTPS, the download page at /, /admin/ proxied to the admin panel. Before that it checks that nginx's config is valid and that no other site serves the domain; if nginx does not accept the new config, the old one comes back;
  • gets the certificate (certbot certonly --webroot, nginx's configs are not edited by certbot); certbot's timer renews it, and the Lumen server picks up the renewed certificate by itself;
  • opens ports 80, 443, 7443 in ufw if it is on. A firewall in the provider's panel must be opened by hand (TCP 80, 443, 7443).

If item 1 finds nginx already installed, it goes on as item 2.

HTTPS :443 ──▶ nginx (other sites + lumen.example.com)
                 ├─ /         /var/www/lumen.example.com  (download page, installer)
                 └─ /admin/   http://127.0.0.1:7480       (admin panel)
Lumen Host / Lumen Client ──TLS :7443──▶ lumen-server (Docker) ── /opt/lumen-server/data

In the programs the server is the domain (lumen.example.com), not the IP: the certificate is issued for the domain.

5.3. A local network (item 3)

Without a domain there is no public certificate, so the server makes its own — for its address, valid for 100 years. The key is made once and kept in /opt/lumen-server/data/tls; updates do not change it.

The script asks for the address devices use to reach the server (it offers the machine's IP; several are allowed, comma-separated, names too) and for the admin's login and password. If ports 443, 80 or 7443 are taken, it offers others (8443, 8080 or off for HTTP, 7444).

HTTPS :443 ──▶ lumen-server: download page at /, admin panel at /admin/   (HTTP :80 → HTTPS)
Lumen Host / Lumen Client ──TLS :7443──▶ lumen-server (Docker) ── /opt/lumen-server/data
Fingerprint. At the end the script prints the certificate's fingerprint: 16 groups of 4 characters. Lumen Host and Lumen Client show it on the first connection and ask whether to trust the server: check that it matches. After that the programs check the key themselves; if it changes (the server was reinstalled with its data deleted — or it is not your server), they refuse to connect and ask again.

Trust by fingerprint is offered only for a local address: an IP address, a name without dots, or a name ending in .lan, .local, .internal, .home.arpa or .localdomain. For a public domain, use items 1–2 with Let's Encrypt.

The browser warns once, when opening the admin panel, that the certificate is not trusted. That is expected: the certificate is the server's own. Choose “Advanced” → “Continue to the site”.

5.4. Ports

PortWho listensWhat for

5.5. Without questions

Everything the menu does, as flags (install.sh --help lists them):

sudo ./install.sh --mode clean --domain lumen.example.com --email admin@example.com --yes
sudo ./install.sh --mode nginx --domain lumen.example.com --yes
sudo ./install.sh --mode lan --address 192.168.1.20 --admin-password 'Secret-2026' --yes
sudo ./install.sh --mode update --yes
sudo ./install.sh --mode remove --keep-data --yes

Without --admin-password a password is generated and printed at the end; --admin-user sets the login (default admin). The password: at least 8 characters, no spaces and none of $ ` ' " \ #. --yes takes the defaults everywhere and needs --mode.

7. Admin panel

Open https://lumen.example.com/admin/ (in a local network https://192.168.1.20/admin/) and sign in with the login and password from .env (after 5 wrong passwords, sign-in from that address is blocked for a minute). It works on a phone too. The tabs are icons at the top; the line at the top shows the sessions and how many clients and machines are online.

  • Requests — a block above the lists on the Clients and Machines tabs; it shows up when there are requests (their number is on the Clients icon). A client asked for access to a machine for the first time: “Approve” or “Reject”. A rejected client cannot ask for that machine again until you press “Lift the ban” in its connections.
  • Clients — alphabetically, under the name the client gave itself in Lumen Client. The administrator can give a client a name of their own (the pencil “Name the client” in the expanded block, Latin letters only); it is seen only in the admin panel. A collapsed block shows the name and status: session (yellow), online (green), offline (grey). A click expands it:
    • the state: who the session is with, at what frame rate and cap, or when the client was last seen;
    • settings of this client: frame rate, bitrate cap, file transfer; what is set for this client is highlighted;
    • connections: the client's machines; each access (a “client → machine” pair) has an ID like 3-7 (client and machine numbers). “Unlink” removes the access and at once cuts off a session in progress — after that the client needs a new request; “Unlink from all” is for an employee who has left. A row's status: request, rejected, busy (another client is connected), version (the Lumen versions differ, no connection is possible);
    • “Remove” — the client's record with all its access.
  • Machines — the same from the other side: all machines alphabetically, in a block the clients with access; “Remove” deletes the machine's registration. While a host installs a new version, the machine shows “Installing a newer Lumen…”; if it fails — “The update failed” with the reason (section 13).
  • Settings — for all clients at once: frame rate, bitrate cap, file transfer, and the file speed cap (default 100 Mbit/s, 1 to 1000, for each side of a session).

Frame rate and cap are set independently: you can limit only the frame rate, only the cap, or both. What is set, the client cannot change (the field is locked in Lumen Client); the rest it chooses itself. A client's own setting comes before the general one, field by field. They take effect from the next connection. The client's file transfer switch also comes before the general one and takes effect at once: turned off during a session, the transfers in progress are cut off. Text and pictures in the clipboard are not affected.

The search at the top (“Find a client or a machine”) is shared by both tabs; a block found by a name inside it expands by itself.

8. Host: Lumen Host

8.1. Installation

Run lumen-setup-<version>.exe, choose the language and then “Host” (the setup restarts itself with administrator rights: Windows asks). Installed into C:\Program Files\Lumen:

  • the Windows service “Lumen Host”: it runs from power-on, also on the sign-in and lock screens, in UAC prompts and in programs run as administrator;
  • Lumen Host, the window for its settings (its tray icon starts at every user's sign-in), and a desktop shortcut;
  • a Windows Firewall rule “Lumen Host (UDP)” for UDP 9000–9009, all profiles;
  • the policy that lets services send Ctrl+Alt+Del (SoftwareSASGeneration), for Ctrl+Alt+Del from a client;
  • optionally, the virtual monitor driver Lumen VDD: the task “Virtual monitors (Lumen VDD driver)”, unchecked by default (8.4).

The host is installed for the whole computer: Lumen Host is the same in every Windows account of this machine, the registration and the token belong to the machine. New versions the host installs from the server by itself (section 13); the same installer run over an installed one also works: the registration and the token stay.

Versions. A client connects only to a host of the same version of Lumen (the version is at the bottom of the Lumen Host and Lumen Client windows, and for every device in the admin panel, at the bottom of its block). You do not need to watch it: a newer client updates the host when it connects (section 13).

8.2. Registration

  1. Open Lumen Host (the desktop shortcut). The first time it shows “Welcome”.
  2. Enter the server: the domain (lumen.example.com; port 7443 is implied) or, in a local network, the IP. The machine name is filled in (the computer's name): before registering you can change it — that is how the administrator and the users see the machine. Latin letters, digits and signs only, up to 64 characters; if the computer's name is in Cyrillic, the field is empty.
  3. Press “Register”. The button is active when the server answers (above it — that the server is reachable, or why not: Lumen Host checks the server every 3 seconds). In a local network Lumen Host first shows the server's fingerprint (5.3). The status becomes “Online”, and the machine's token appears: XXXX-XXXX-XXXX-XXXX-XXXX-XXXX.
  4. Give the token to those who will connect (the “Copy” button). It can be seen at any time, from any account of this machine, on the Machine tab.

“Change the token” (the circular arrow next to the token) — if the token got to the wrong people: the old token no longer connects to the machine, every user has to enter the new one (no new approval is needed).

“Remove registration” — the host stops working: if the server is reachable, the machine's record is removed there too (with the clients' access). If the server is unreachable, the administrator removes the record in the admin panel. The token stays the same: after a new registration the clients' cards are right, only the administrator's approval is needed. The server and the name of a registered machine do not change: to change them, “Remove registration”, then “Register” with the new ones.

If the server does not know the machine (the server's database was reset, the machine was removed in the admin panel), Lumen Host says “The server does not know the machine” and shows “Register”: it registers the machine again with the same token. “Token taken” — an old record is left on the server (the machine was unregistered here while the server was unreachable): remove it in the admin panel or press “Change the token”.

8.3. Day-to-day work

  • The host is a service: it works without the Lumen Host window and before anyone signs in to Windows. The window closes to the tray.
  • Turning the host off — right-click the tray icon → “Turn off the host and quit”: the host turns off (if someone is connected, Windows is locked first), nobody can connect. To turn it on again, start Lumen Host (the shortcut) or press “Turn on the host” in its window.
  • “Start with Windows” (on by default) — the host starts when the computer boots, before anyone signs in: after a restart or after turning the host off in the tray, the machine is reachable again. Without it, the host starts only with Lumen Host. The tray icon appears at sign-in while the host is on.
  • “Update when a newer client connects” (on by default) — see section 13.
  • “Keep the computer from sleeping” (off by default) — while the service runs, the computer does not go to sleep by itself, even if sleep is set up in Windows. For the whole machine. Sleep from the Start menu and closing a laptop's lid still work; the monitor turns off by its own timer.
  • Log — on the Settings tab, “Open folder” opens the host's log folder %ProgramData%\Lumen\host\logs (section 12).
  • The settings are shared. The server, the machine name and the token are one per computer: any user signed in to Windows on this machine can change them (and “Change the token”), and that applies to everyone.
  • Who can connect. The machine is always reachable: on the sign-in screen, on the lock screen and in any account; you sign in to Windows with your own password. A session goes on even if someone signs in to another account. One session per machine at a time: others see “Busy”.
  • Lock after a session. The user closed the video window — the host locks Windows at once. The connection broke — after 10 seconds, unless the same user reconnects in that time; if another user connects — at once, before the first frame. Nobody's desktop stays open, neither on the machine's monitor nor for the next connection. If the user has “Do not lock Windows after the session” on in Lumen Client, the host does not lock Windows after that user's session (neither on closing nor on a broken connection); before another user's session it still locks.
  • Several users of one machine. The first one worked and disconnected: their account is locked, programs keep running. The second connects (the same token), chooses “Switch user” on the lock screen and signs in with their own password; the video window reconnects by itself.
  • Restart from the client. A user with approved access can restart the machine from Lumen Client (9.2): Windows restarts at once, open programs close without saving.

8.4. Virtual monitors

The host can add up to two virtual monitors to the machine's monitor: Windows sees them as real ones, and you can move windows onto them. This needs the Lumen VDD driver, which ships inside the installer: when installing the host, check the task “Virtual monitors (Lumen VDD driver)” (unchecked by default; if the setup asks for a restart, restart). Without the driver everything works, the Monitors tab in Lumen Host says that the driver is not installed. A client gets at most three monitors: with two real ones you can add one virtual, with three or more — none. Real monitors are set up in Windows. Installing a new version over without the task updates an installed older driver and installs none where there is none; uninstalling Lumen removes the driver. A computer without a monitor — see 8.5.

In Lumen Host, the Monitors tab:

  • The layout: real monitors are grey, with a lock, and do not move. Virtual ones are yellow; dimmed — turned off or not created yet, dashed — changed and not applied, red — over the limit of three.
  • Place — drag a virtual monitor with the mouse: it snaps to a neighbour's edge (its start, middle or end), Esc cancels. A monitor attaches only to a monitor with a lower number: put monitor 2 next to monitor 3 and they swap numbers.
  • Resolution (16:9, 16:10, 21:9; always 60 Hz) and scale (100–200 %) — in the panel on the right, for the selected monitor.
  • “+” adds a monitor, the cross in its corner removes it. Changes take effect with a button: “Create” — create the monitors; “Apply” (the screen blinks: Windows rearranges the monitors); “Cancel” — back as it was.
  • “Turn off” — the monitors disappear, the settings stay; “Turn on” brings them back. The bin — remove all virtual monitors and their settings.
  • The monitors exist while the host is on (the service): from power-on, on the sign-in screen and in any account. Turn the host off in the tray — the monitors disappear, the settings stay; turn it on — they come back in the same places.
  • The settings belong to the machine, shared by all accounts (%ProgramData%\Lumen\monitors.json, written by the service). Windows keeps the scale per user: Lumen Host sets it at each user's sign-in.
  • The client sees all the machine's monitors — how to show them, see 9.3.

8.5. A computer without a monitor

If the host has the Lumen VDD driver (8.4) and Windows sees no physical monitor (the cable is out, the monitor is off and gone from the system), you can still connect: for the time of the connection the host creates this client's virtual monitors. “Client” here is a Lumen Client installation: a person's laptop and desktop have monitors of their own. A monitor emulator plug (HDMI dummy) is a physical monitor for Windows.

  • The first connection of a client: Lumen Client shows “The remote computer's monitor” — choose the resolution and scale (preselected as your monitor's) and press “Create”. The choice is kept on the host; the next connections go without the question.
  • Change the resolution and scale or add monitors (up to three in all) — during the connection, in Lumen Host on the remote computer, the Monitors tab: it shows the connected client's monitors. Monitor 1 stays in place, its resolution and scale change; the others are placed next to it as in 8.4. Changes — with “Apply”; they are kept for this client. Lumen Client has no reset.
  • The end of the connection: the video window closed — the monitors go at once; the connection broke — after 10 seconds, unless the same client is back. Windows locks as usual (8.3).
  • The machine's shared virtual monitors (8.4) are not created without a physical monitor. A physical monitor plugged in during a connection — from then on as usual (the physical and the shared virtual ones), the client's monitors stay saved; unplugged — the client's monitors at once (if there are none yet, Lumen Client asks for the resolution again).
  • No driver — the connection does not start; Lumen Client shows the machine as “No monitors”.

9. Client: Lumen Client

9.1. Installation

Run lumen-setup-<version>.exe, choose the language and “Client”. The client is installed for the current Windows user (%LOCALAPPDATA%\Programs\Lumen) and needs no administrator rights. On the first start — the “Welcome” page: your name (the administrator sees it when approving a connection; Latin letters, digits and signs only) and your organisation's server (the administrator gives you the address). “Continue” checks the server at once; in a local network it shows the certificate's fingerprint (5.3). A client has one server. The language is the installer's; the globe switches it.

9.2. Machines

  1. The name and the server are in the settings. While there are machines in the list they do not change; to change them, remove all machines (removing the last one removes this computer from the server too, and the administrator approves the requests again).
  2. On the machines tab press “Add a machine” and enter the token that Lumen Host shows. The token is hidden in the list; a click shows it. On disk the machines' tokens are encrypted for your Windows account (DPAPI): the settings file copied to another computer or account will not open them.
  3. The status says “Awaiting approval”. When the administrator approves — “Online”.
  4. “Connect” opens a window with the machine's screen. While connecting, the status shows how it goes (cancel with “Disconnect”); as soon as the video window appears, Lumen Client leaves the screen and the taskbar, and comes back when the video window is closed.
  5. Options (the “…” button of a machine): “Restart” — restarts the remote machine at once (only with approved access and while the machine is online): whoever is connected is disconnected, open programs close without saving; in a minute or two the machine is online again, at the Windows sign-in screen. “Remove the machine” — removes the machine and its request on the server (Lumen Client asks first). When the last machine of the server is removed, this computer is removed from the server too (if the server is unreachable, the administrator removes the record in the admin panel).

9.3. The video window

  • The mouse and the keyboard go to the host, Esc and Alt+F4 included, and while the video window is in front, also the system shortcuts (Win, Alt+Tab and so on, see 9.8).
  • Close the window — Ctrl+Alt+Shift+Q or the window's cross. Ctrl+Alt+Del on the remote machine — Ctrl+Alt+Shift+Del (a plain Ctrl+Alt+Del always acts on your computer).
  • The window can be resized and maximised: the picture fits with its proportions kept, the rest is black. Borderless over the whole monitor and back — Ctrl+Alt+Shift+F (the session goes on).
  • A machine without a monitor (8.5): on the first connection the status is “Choosing a monitor” and the window “The remote computer's monitor” asks for the resolution and scale — “Create”; “Disconnect” — give up the connection. “No monitors” — the machine has no virtual monitor driver.
  • Several monitors on the machine (real or virtual, see 8.4). At most three are shown: the primary, then the other real ones by their Windows number, then the virtual ones. A monitor plugged into a non-NVIDIA output (for example the integrated graphics) is not shown. Three views, Ctrl+Alt+Shift+L cycles through them:
    1. all in one window — the monitors as on the machine, scaled down to fit;
    2. one monitor per window — circles I / II / III at the top, a click shows that monitor; the machine sends only the one shown; the mouse stops at its edge;
    3. a window per monitor — spread the windows over your monitors; Ctrl+Alt+Shift+F makes all of them borderless, each on its own monitor (two windows on one monitor — refused with a hint). Closing any window ends the connection.
    The view, the monitor shown and the windows' places (with or without a frame, maximised) are kept on the machine's card: the next connection is as before. If the machine's monitors have changed since (number, resolution, arrangement), the connection starts in view 1; if they change during a connection — also view 1, without breaking the connection.
  • The sharpest picture (small text, colour) is at 1:1 — a host pixel to a screen pixel. You get it when the window is exactly the host screen's size: a framed window opens so if the host's screen fits on the monitor (do not stretch it), a borderless one if the host's and the monitor's resolutions match. A stretched or shrunk picture is smoothed.
  • The cursor feels “sticky” — check that this computer has no frame limiter: “Max Frame Rate” in the NVIDIA Control Panel, RTSS and similar programs (a 90 fps limit did that on a 120 Hz monitor).

9.4. Clipboard and files

  • Text (up to 1 MB) — shared: copied on the remote machine, paste it here, and back. Only what is copied after connecting goes across: the clipboard's earlier contents stay on their machine. Your text goes to the remote machine only while the video window is in front: what you copy in other programs (a password, say) stays with you until you switch to the video window. Pictures in the clipboard (an area from Photoshop, a screenshot) go across the same way, byte for byte, up to 32 MB.
  • Files and folders — through the clipboard too, both ways: copy them (Ctrl+C) on one machine and paste (Ctrl+V) on the other. There is no drag and drop.
    • Up to 32 MB (everything copied at once) — like a normal clipboard: the files go right after copying, Ctrl+V pastes them where you paste (a folder, the desktop).
    • Over 32 MB — the transfer starts on Ctrl+V or Shift+Insert (not from the “Paste” menu), without questions, and the files go to the Downloads\Lumen folder (C:\Users\<user>\Downloads\Lumen) of the machine where you pressed it. A name taken — “(1)” is added.
    • The progress is in the picture's lower right corner: each download is a block of its own, new ones below: name, direction, size, progress, speed, time left and “Cancel”; with more than one transfer, “Cancel all” at the top. The panel opens by itself during a download and hides 5 s after the last one ends; Ctrl+Alt+Shift+D shows or hides it; with no transfers — this session's history (done, cancelled, failed — with the reason).
    • Files up to 32 MB do not open the panel by themselves; their progress is the “Clipboard” line at the bottom of the panel (open it with Ctrl+Alt+Shift+D): everything copied as one line, because there is one clipboard and it is overwritten.
    • While files come from the remote machine to you, the video gets coarser (they share the link), and recovers afterwards. The administrator caps the file speed (default 100 Mbit/s).
    • The connection broke — after reconnecting the transfer goes on from the same place. Every file's integrity is checked; an unfinished one lies as name.part and is deleted on cancel.
    • Nothing goes across: if the administrator turned files off (“file transfer is turned off by the administrator”); while nobody is signed in to Windows on the remote machine (sign-in screen) or it is locked (“the host is locked — sign in to Windows on the host”: sign in and paste again); if the disk is full.

9.5. Sound

The remote machine's sound is always heard here, nothing to turn on: whatever Windows plays there on the default output device (Opus, 128 kbit/s, stereo) comes out of this computer's default output device. The volume is set as usual, on this computer. The remote machine keeps playing its sound too. If the remote machine has no output device (no speakers, no sound over HDMI/DP), there is no sound — the overlay says “none”. The sound's latency is about 40 ms plus the network; with packet loss it breaks less often than the picture (each packet also carries the previous piece of sound).

9.6. Overlay

Ctrl+Alt+Shift+O turns it on and off: a block at the bottom centre of the picture (on the picture itself, not on the black margins; it shrinks with it) that shows whether everything is fine and where lags come from. The header states it in words (green — “All good”, yellow — worth a look, red — a problem).

  • Metrics: latency (from the remote computer's screen to yours, ms), smoothness (how many of the set frames per second are shown), network response (round trip), packet loss, stream (the video's bitrate and its cap), sound (ms from the sound on the remote machine to the sound here; yellow — the sound broke up recently, “none” — no sound).
  • Latency over 10 seconds — three graphs on one scale: host (capture and compression), network, this computer (decoding and display); a red mark is a lost frame.
  • Video — resolution, capture (the host's desktop in RGB 8 bit), codec, bit depth and chroma subsampling, colour space and range, for example “3840×2160 · capture RGB 8 bit → HEVC 10 bit 4:2:0 · BT.709, full range”.
  • With several monitors the overlay is on the first one's picture; in the “window per monitor” view — only in the main window.

9.8. Settings

Settings are saved at once and take effect from the next connection. The keyboard shortcuts are on the help tab. The log's “Open folder” opens the folder of the log files.

  • Update automatically (on by default) — see section 13.
  • Frame rate 30 or 60 fps and bitrate cap (Auto — by the resolution and frame rate; or 10–100 Mbit/s) — for all machines. If the administrator sets them, the fields are locked. The cap is fixed: Lumen does not lower the quality by itself; on packet loss the host repairs the picture instead of resending a whole frame.
  • Video window without a frame — the video window opens borderless over the whole monitor. The picture always fits the window: larger than the screen — shrunk, smaller — enlarged, proportions kept (black margins at the edges).
  • System shortcuts to the remote machine (on by default) — while the video window is in front, Win, Alt+Tab, Alt+Esc, Ctrl+Esc, Ctrl+Shift+Esc, PrintScreen and other Windows shortcuts go to the host, not to your computer. To get to your own windows, minimise or close the video window (Ctrl+Alt+Shift+Q) or turn this setting off. Ctrl+Alt+Del and Win+L always stay on your computer.
  • Do not lock Windows after the session (off by default) — when the session ends (you closed the video window or the connection broke), the remote machine stays as it is: programs open, no password to enter. Mind that its desktop is open to anyone sitting at it. If another user connects next, Windows is still locked before their session.

10. First connection, step by step

  1. Network: WireGuard or Tailscale, the client pings the host (section 4).
  2. The server is installed, the admin panel opens (section 2, section 7).
  3. On the host: install with “Host”, open Lumen Host, enter the server, “Register”, copy the token (8.2).
  4. On the client: install with “Client”, enter your name and the server on the Welcome page, then “Add a machine” with the token (9.2).
  5. In the admin panel, in the Requests block — “Approve”.
  6. In the client — “Connect”.

11. Deploying to many machines

The installer runs without questions:

lumen-setup-0.9.0.exe /VERYSILENT /SUPPRESSMSGBOXES /ALLUSERS /TYPE=host
lumen-setup-0.9.0.exe /VERYSILENT /SUPPRESSMSGBOXES /ALLUSERS /TYPE=host /TASKS="desktopicon,vdd"
lumen-setup-0.9.0.exe /VERYSILENT /SUPPRESSMSGBOXES /TYPE=client
  • The host — as administrator and always with /ALLUSERS; the second line adds the Lumen VDD driver (8.4; /TASKS="vdd" — without the desktop shortcut). Whether a restart is needed is not reported by the exit code: look in the setup's log (/LOG="C:\lumen-setup.log"), the line lumen-vdd-setup install: 3010.
  • The client — as the user who will use it (it goes into their profile, without administrator rights).
  • Without the desktop shortcut — add /TASKS="".
  • The host's registration (one per machine, from any account) and the client's machines are done in the programs.

Uninstalling — Settings → Apps → Lumen. The uninstaller asks whether to delete user data (default: no). With the box checked, for a host: the machine's key, registration and token, the host's and the virtual monitors' settings, the logs (for all Windows users of the computer); for a client: this user's key, name, server, machines, settings and logs. A new install then starts from scratch: the machine gets a new token, the server sees the client as a new computer, access is approved again; remove the old records in the admin panel. Without the box, the data stays and a reinstall goes on from where it was. Without questions — unins000.exe from the program's folder, with the data — add /PURGE=1:

"C:\Program Files\Lumen\unins000.exe" /VERYSILENT
"%LOCALAPPDATA%\Programs\Lumen\unins000.exe" /VERYSILENT /PURGE=1

13. Updates

A new version comes with the server: the server's archive contains the installer of its version. Update the server (14.2), and Lumen Host and Lumen Client see that they are older than the server and install its version by themselves, without windows and without administrator rights. Before installing they check the size and the checksum of the download; they never go back to an older version.

  • The yellow footer at the bottom of the Lumen Host or Lumen Client window — “Your version is out of date. Click to update”: the server has a newer version. Click → confirm → the program closes, installs the new version and starts again (a session in progress is cut off). This works at any time, whatever the switches below say.
  • Lumen Client, “Update automatically” (settings, on by default): at start the client checks the server (for a few seconds at most) and, if there is a newer version, installs it right away and starts already updated. The server did not answer — the installed version starts with the yellow footer. While the client is open it does not update itself. Without the switch — only by clicking the footer.
  • Lumen Host, “Update when a newer client connects” (settings, on by default): the host updates when a client of a newer version connects to it — quietly, by the service itself, also with Windows locked. The client shows “Host is updating…” and connects by itself a few seconds later. While another user is connected, the machine is busy and does not update. Without the switch — only by clicking the footer.
  • It failed (the download, the checksum, the installer, an antivirus) — the program keeps working on the old version, the reason is in the footer. A host's failure is also seen by the client (“Host update failed”) and in the admin panel, in the machine's block. The server hands out updates to at most 16 devices at once (“The server is busy with other updates; try again later”).

The usual order: update the server → users start Lumen Client (it updates itself) → they connect to their machines (the hosts update themselves). Nothing needs to be installed on the machines by hand.

The installer is not digitally signed yet: Windows SmartScreen may warn about it (“More info” → “Run anyway”), and the programs trust the server they are connected to. So update the server only from an archive you built yourself or downloaded from a trusted place (GitHub Releases), and do not give strangers access to the server.
Coming from a version older than 0.7.0 — once, by hand: on the client computers first uninstall the old Lumen (Settings → Apps → Lumen): the client now installs per user, not into Program Files, and the new installer does not remove the old one. The client's machine cards are not carried over: on the first start enter the name and the server and add the machines by token again; the client's key (%APPDATA%\Lumen) survives the uninstall, so the server recognises the computer and the approved access stays. The host installs over the old one as usual. After that the programs update themselves.

14. Server maintenance

Status, update and removal — install.sh: it copied itself to /opt/lumen-server during the installation, so status and removal need no archive.

14.1. Status

sudo /opt/lumen-server/install.sh --mode status (or the menu item 5) shows the version, the mode, whether the container runs, the addresses, the admin's login, the fingerprint (local network) or the certificate's expiry (domain) and the end of the log.

14.2. Update

Upload the new version's archive, unpack it and choose “Update” (offered by default when a server is installed):

cd /tmp && tar xzf lumen-server-0.9.0.tar.gz
sudo bash lumen-server-0.9.0/install.sh --mode update

The database, the settings and the key (the fingerprint) stay; the image, the download page and the installer the server gives the programs are updated, older images are removed. The script asks before installing a version older than the installed one. The programs then update themselves (section 13). A server installed by hand the old way (the archive unpacked into /opt/lumen-server, nginx set up by hand) is updated the same way: the script keeps your nginx config and removes the old leftovers.

14.3. Changing settings

The settings are in /opt/lumen-server/.env (for example LUMEN_ADMIN_PASSWORD; values without $). After editing, restart the container:

cd /opt/lumen-server && docker compose up -d

To change the mode or the domain, remove the server keeping the data (14.5) and install it again: the database is picked up.

14.4. Commands without the browser

On the server, as root: the log and the administrator's commands (the same database as the admin panel). IDs come from hosts and clients; approve 3 7 approves client 3 for machine 7.

docker logs --tail 50 lumen-server
docker exec lumen-server lumen-server access --status pending
docker exec lumen-server lumen-server hosts
docker exec lumen-server lumen-server clients
docker exec lumen-server lumen-server approve 3 7
docker exec lumen-server lumen-server files show
docker exec lumen-server lumen-server --help

Others: reject, unlink, unlink-all, remove, override (frame rate and cap), files (file transfer and its speed cap), cap (the Auto caps by resolution and frame rate).

14.5. Removal

sudo /opt/lumen-server/install.sh --mode remove (or the menu item 6) removes the container, the images, our nginx site and the download page, and the ufw rules the script opened. It asks whether to delete the database and the key: if kept (the default), they stay in /opt/lumen-server/data and a new installation picks them up (the same fingerprint, devices and access). It also asks whether to delete the Let's Encrypt certificate (default: no). Docker and nginx stay installed.

15. Troubleshooting

15.1. Server installation

The script stops at a line with ✗ and says why and what to do. Nothing is left half done: if nginx did not accept our config or certbot did not get the certificate, nginx goes back to what it was. Fix the cause and run the script again.

What you seeWhat to do
“The domain … does not resolve”The A record is not there yet or has not propagated: getent hosts lumen.example.com, wait and run again.
“certbot did not get the certificate”Port 80 is closed (ufw or the provider's firewall) or the A record points elsewhere. Our site is removed from nginx — just run again.
“… is already served by nginx”The domain is in another nginx config (the script names it). Use another subdomain or remove that site.
“nginx's config has an error already”The error was there before: fix it (nginx -t), then run the script.
“Port … is taken”The script says by whom. In a local network you can choose another port; with a domain, port 7443 must be free.
“The server did not start”The log is printed above it (docker logs lumen-server).
The admin panel does not opensudo /opt/lumen-server/install.sh --mode status: is the container running, the end of the log.
